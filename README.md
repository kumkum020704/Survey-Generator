# Synthetic Survey Response Generator

Turns a declarative survey definition into **N realistic, internally-coherent
synthetic responses**. Built for the "E-commerce Customer Satisfaction" brief,
but the schema is generic — point it at any survey JSON.

It handles **rating scales (1–5)**, **NPS (0–10)**, **single-choice**, and
**open-text** questions, and ships with a validation suite that *measures*
whether the output is plausible and coherent.

> No third-party dependencies. Pure Python 3.10+ standard library.
> Runs with **zero API cost**. An optional LLM mode (Google Gemini) is
> available but off by default.

---

## Quick start

```bash
# Generate 200 responses for the demo survey.
# --seed makes a run reproducible: the SAME seed always gives the SAME 200
# responses. Change the number for a different-but-reproducible dataset, or
# omit --seed entirely for fresh random responses on every run.
#   --seed 47  -> dataset A (repeatable)
#   --seed 5   -> dataset B (different from A, but repeatable)
#   (no seed)  -> brand-new responses each time you run it
python generate.py --survey survey.json --n 200 --seed 47 --report

# Outputs:
#   responses.csv          flat table, one row per respondent
#   responses.json         same data + survey metadata
#   validation_report.md   plausibility + coherence + diversity metrics

# Peek at a few rows without writing files
python generate.py --survey survey.json --n 6 --preview --no-files

# Validate an existing file at any time
python analyze.py --survey survey.json --responses responses.json

# Run the test suite
python test_surveygen.py        # or: python -m pytest test_surveygen.py
```

## How it works (the short version)

The core is a **causal latent-trait persona model**, not a bag of independent
random draws and not a single LLM prompt.

1. Each synthetic respondent is sampled from a **persona segment**
   (`delighted_loyalist`, `satisfied_regular`, `neutral_pragmatist`,
   `frustrated_shopper`, `detractor`) whose population weights give the data its
   realistic, slightly right-skewed shape.
2. The segment sets a **hidden satisfaction trait** plus drivers like delivery
   timeliness and purchase category.
3. **Every visible answer is sampled conditioned on that shared hidden state.**
   The rating, the NPS score, and the open-text comment are all noisy reads of
   the *same* disposition, so they cannot contradict each other.

```
   persona segment ─┐
   category ────────┼──► delivery_on_time ─┐
                    │                        ├──► satisfaction (latent) ──► rating
                    └────────────────────────┘            │                └─► NPS
                                                           └──► open-text themes
```

A late delivery lowers satisfaction, which lowers the rating *and* the NPS *and*
makes the open-text comment more likely to mention slow shipping — automatically.

See [`WRITEUP.md`](WRITEUP.md) for the full reasoning, evaluation strategy, and
what I'd do with more time.

## Project layout

```
survey.json              # the demo survey definition (generic schema)
generate.py              # CLI: produce N responses (+ optional report)
analyze.py               # CLI: validate any responses file
test_surveygen.py        # statistical + schema tests (11 cases)
surveygen/
  schema.py              # survey loading & validation
  personas.py            # persona segments and their priors
  engine.py              # the causal latent-trait generator
  opentext.py            # theme-conditioned open-text writer
  validate.py            # plausibility / coherence / diversity metrics
  llm.py                 # optional LLM open-text augmentation (Gemini)
```

## Hybrid design: rule-based structure, optional LLM prose

Structured fields — satisfaction, NPS, category, and delivery status — are
generated by the persona model and never touched by an LLM. Coherence is a
structural guarantee from the causal model.

The open-text field is the one place an LLM adds clear value: the template
engine already produces sentiment-appropriate comments for free, but an LLM can
express the same meaning with more natural-sounding phrasing. When enabled, it
**rewrites only the open-text field**, strictly conditioned on each respondent's
already-decided rating, NPS, category and delivery outcome — so coherence is
never at risk.

The LLM layer uses **Google Gemini** (`gemini-2.5-flash-lite` by default — it is
built for high-volume short text and carries the most generous free-tier quota,
so a 200-row run is far less likely to hit a rate limit). Override the model with
`--llm-model` if you prefer, e.g. `--llm-model gemini-2.5-flash`.

Calls retry transient errors (503/429/timeout) with exponential back-off, and
each returned answer is sanitised + length-checked; any batch that still fails
falls back to the template text. The run prints an honest summary, e.g.
`[llm] 10/10 batches succeeded — 200 open-text answer(s) rewritten` (or how many
fell back), so a quietly-degraded run can never look like a clean LLM run.

### Enable via environment variables (or a .env file)

`generate.py` auto-loads a `.env` file in the project root (no extra dependency).
Copy `.env.example` to `.env` and fill in your key — or export the vars by hand:

```bash
pip install google-genai
cp .env.example .env                   # then edit .env, OR export manually:
# Get a free key at https://aistudio.google.com/apikey
export GEMINI_API_KEY=your_key_here    # PowerShell: $env:GEMINI_API_KEY="..."
export ENABLE_LLM_TEXT=true            # PowerShell: $env:ENABLE_LLM_TEXT="true"
python generate.py --survey survey.json --n 200 --seed 47
```

### Enable via CLI flag (alternative)

```bash
python generate.py --survey survey.json --n 200 --seed 47 --llm
```

Both methods are equivalent. If `GEMINI_API_KEY` is missing or `google-genai`
is not installed, the generator prints a notice and falls back to the template
engine — the run always completes.

## Adapting to a different survey

Edit `survey.json`. Each question needs a `type`
(`rating` / `nps` / `single_choice` / `open_text`) and, optionally, a `role`
that lets the coherence engine wire it into the causal model
(`satisfaction`, `nps`, `category`, `delivery_on_time`, `open_feedback`).
Questions without a recognised role still get plausible, type-appropriate
answers — the generator never breaks on an unfamiliar survey.
